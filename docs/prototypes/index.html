What was actually broken in the live app (measured, 2026-10-13)
SurfaceMeasured behaviourFix this prototype assumes
Login Live API answers 400 in 2.6s; component state becomes loading:false, error:"Invalid login ID or password" but the DOM still reads “Signing in…”, button disabled, role="alert" count 0 — stuck forever. One owner of the busy flag; every path clears it and renders the message + a way forward.
Reports, Platform dashboard, Business settings Error content rendered inside class="panel loading" — failures are styled as loading. Distinct .state-panel styling, never a loading class.
Live Orders, Reports, Terminals, Feature flags Error block with no retry action; several without role="alert". Every error carries one primary action and is announced.
Global interceptor Network and 5xx failures go to console.error only — the user sees nothing. Toast + inline surface, with errors lingering 7s instead of 3.5s.
