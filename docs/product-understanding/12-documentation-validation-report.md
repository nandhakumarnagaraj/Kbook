### 2.6 Area 6: Roles — Are Frontend and Backend Permissions Consistent?
- **Forensic Investigation:**
  - Let $K$ be the set of 27 `PermissionKey` values defined in `PermissionKey.java`.
  - **Server `PermissionService.java`:**
    ```java
    SHOP_STAFF_CONFIG_KEYS = Set.of(
        SETTINGS_SHOP_PROFILE, SETTINGS_PAYMENT, SETTINGS_PRINTER, SETTINGS_TERMINAL,
        SETTINGS_GST, STAFF_VIEW, STAFF_ADD, STAFF_EDIT, STAFF_REMOVE, STAFF_PERMISSIONS,
        MENU_TOGGLE_AVAILABILITY, MENU_EDIT_PRICE, MENU_EDIT_FULL, MENU_ADD_ITEM,
        MENU_DELETE_ITEM, REPORTS_EXPORT
    ); // 16 keys
    SHOP_STAFF_GRANTED_KEYS = ALL - SHOP_STAFF_CONFIG_KEYS; // 11 keys
    ```
    Granted to Staff: 11 keys (`billing.*` [6 keys], `menu.view` [1], `orders.view` [1], `reports.day_summary` [1], `reports.full` [1], `reports.gst` [1]).
  - **Android `PermissionManager.kt`:**
    ```kotlin
    SHOP_STAFF_CONFIG_KEYS = setOf(
        MENU_TOGGLE_AVAILABILITY, MENU_EDIT_PRICE, MENU_EDIT_FULL, MENU_ADD_ITEM,
        MENU_DELETE_ITEM, REPORTS_EXPORT, SETTINGS_SHOP_PROFILE, SETTINGS_PAYMENT,
        SETTINGS_GST
    ) // 9 keys
    SHOP_STAFF_GRANTED_KEYS = ALL - SHOP_STAFF_CONFIG_KEYS // 18 keys
    ```
    Granted to Staff: 18 keys.
- **Audit Verdict:** **DIVERGENCE IDENTIFIED.**
  - An exact 7-key divergence exists: `settings.printer`, `settings.terminal`, `staff.view`, `staff.add`, `staff.edit`, `staff.remove`, and `staff.permissions` are treated as *granted* on Android POS, but marked as *denied config keys* on the server.
  - **Why it does not fail in production:** `settings.printer` operates against local SQLite `printer_profiles` without touching the server, and staff cannot log in to Web Admin. However, the permission definitions between Android and Spring Boot are architecturally divergent.

### 2.7 Area 7: Multi-Tenancy — Is Restaurant Isolation Enforced in Every Relevant API?
- **Forensic Investigation:**
  - Scanned all JPA queries and controllers across `services/server/src/main/`.
  - Found **102 references** to `TenantContext.getCurrentTenant()`.
  - `JwtFilter.java` validates incoming bearer tokens and populates `TenantContext`.
  - `GenericSyncService.java:198`:
    ```java
    Long tenantId = TenantContext.getCurrentTenant();
    if (tenantId == null) throw new UnauthorizedException("Tenant context is required");
    ```

  - Delta sync push verifies that every pushed item matches `record.getRestaurantId().equals(tenantId)`. Cross-tenant ID injection is blocked.
  - `TerminalRequestFilter.java` cryptographically validates `X-Terminal-Token`, overriding any client-provided `deviceId` with the verified terminal device ID.
- **Audit Verdict:** **VERIFIED.** Multi-tenant isolation is enforced at the JWT filter, service layer, and database query levels.

## 5. Critical Product Gaps & Technical Debt

1. **Permission Key Parity Gap:** Harmonize `SHOP_STAFF_CONFIG_KEYS` between Android `PermissionManager.kt` and Server `PermissionService.java` so both enforce the identical set of keys.
2. **Dormant Inventory UI in Web Admin:** Either remove `/business/inventory` from Angular routes or build a simplified finished-dish stock tracker since raw-material tables were dropped in V127.
3. **Multi-Restaurant Switch on Same Device:** Fix `TerminalController.java` to permit an authenticated `OWNER` to switch between restaurants without triggering `TerminalPendingApprovalException`.
4. **Single Master Database Bottleneck:** Single PostgreSQL instance represents a single point of failure for cloud analytics.
