2. DECONSTRUCTION OF AROW APP (APK & WEB KDS HAR LOGS)
--------------------------------------------------------------------------------

From decompilation of the Arow APK and deep inspection of the Chrome HAR capture
from https://www.arowapp.com/kds (specifically chunk `0xqo4iag.-0p6.js`), the
exact mechanics of Arow were reverse-engineered:

A. Zero-Authentication Web KDS Pairing:
   1. Browser visits `arowapp.com/kds`.
   2. Generates a random `deviceId`: "device_" + Math.random().toString(36).substr(2, 9).
   3. Saves `arow_kds_device_id` into browser localStorage.
   4. Writes a document to Firestore: `kds_devices/{deviceId}` with status="waiting".
   5. Renders a QR code containing `deviceId` on the TV/browser screen.
   6. Waiter/manager opens Arow mobile POS, taps "Scan KDS QR", scans screen.
   7. Mobile app writes `{ outletId: "outlet_123", status: "paired" }` to `kds_devices/{deviceId}`.
   8. Browser Firestore snapshot triggers instantly, loads outlet profile, and transitions
      into the live kitchen view without entering usernames or passwords.

B. Live Ticket Stream & Audio Alarm:
   1. The browser queries `outlets/{outletId}/kots` where status IN ["pending", "cooking"].
   2. Compares incoming item snapshot array against in-memory map.
   3. If new KOT arrives or items change, it triggers `audio.play('/siren.mp3')`.

C. Batch Cook Summary Drawer:
   1. Iterates all pending tickets and aggregates identical items:
      Summary[(name, variant)] = SUM(qty).
   2. Displays a floating badge & sidebar: e.g. "Total 14 Roti, 5 Butter Chicken,
      3 Paneer Tikka needed right now". Chefs can batch cook without reading 10
      separate tickets.

D. Visual Dine-In Floor Management:
   1. Categorized by floors: Ground Floor, 1st Floor, Rooftop, Garden.
   2. Tables show occupancy color:
      - Green/Gray: Vacant
      - Orange: Occupied with elapsed seating timer ("34 mins")
      - Purple: Bill Printed (guest asked for check)
   3. Table transfer: reassigns running bill to another table.
   4. Table merge: merges items from two tables into a unified bill.

3. KHANABOOK'S CURRENT ARCHITECTURE & DEFICITS
--------------------------------------------------------------------------------

An exhaustive audit of KhanaBook's codebase reveals the exact gaps:

1. Dine-In Tables:
   - BillEntity.kt has `customerName` and `orderType` ("dine_in" or "takeaway").
   - In CartStep.kt line 317: `label = { Text("Table name / Customer name") }`.
     The cashier literally types "Table 3" into an open text box.
   - ActiveOrdersScreen.kt displays unpaid bills in a vertical card list. There is
     no floor layout, no visual grid, no seating timer, and no occupancy state machine.

2. Kitchen Display (KDS):
   - ReprintKdsScreen.kt is misnamed: it is simply an invoice/daily-id search screen
     to reprint a paper thermal receipt via Bluetooth or Wi-Fi ESC/POS printers.
   - There is no web display, no real-time stream, and no kitchen screen.

3. Printer Routing:
   - PrinterProfileEntity.kt enforces:
     `indices = [Index(value = ["restaurant_id", "role"], unique = true)]`
     where role is either "customer" or "kitchen".
   - Only ONE kitchen printer can be registered! Outlets cannot route drinks to a
     Bar printer and food to a Kitchen printer.

4. Menu Variants vs Modifiers:
   - ItemVariantEntity.kt only supports flat 1-level variants (Half / Full).
   - There is no concept of Modifier Groups (e.g. "Choose Bread", "Extra Toppings")
     or min/max rules (compulsory vs optional).

5. Pricing:
   - MenuItemEntity.kt has a single `basePrice`.
   - Outlets charging higher prices for AC dining or Swiggy/Zomato delivery have
     to manually create duplicate items in the catalog.

6. Coupons & Khata:
   - BillEntity.kt has no `discountAmount` or `couponCode`.
   - Customer credit (Udhar) cannot be tracked cumulatively.

4. STRATEGIC ADVANTAGES KHANABOOK CAN EXPLOIT (THE "UNFAIR MOATS")
--------------------------------------------------------------------------------

Arow App's Achilles heel is that it is fundamentally CLOUD-BOUND.
If an Indian restaurant loses internet connectivity:
- Arow's web KDS stops receiving orders.
- Arow's multi-device table synchronization halts.
- Operations freeze.

KhanaBook already has an offline-first architecture:
1. Room Database (SQLite) on Android executes reads/writes in under 1 millisecond.
2. Terminal sequence counters (terminalSeries + invoiceSequence) ensure guaranteed
   zero-duplicate invoicing offline.
3. MasterSyncProcessor queues changes and merges them seamlessly when online.

KhanaBook can build:
- Zero-Latency Table Grid: Renders instantly from local Room DB without spinners.
- Dual-Mode KDS (The Killer Differentiator):
  * When online: Spring Boot Server-Sent Events (SSE).
  * When broadband is cut: The Master Android POS runs a lightweight embedded
    HTTP/WebSocket server on the local Wi-Fi router (e.g. 192.168.1.50:8080/kds).
    The Kitchen TV continues receiving tickets over local Wi-Fi without internet!

5.2 WEB & TV KITCHEN DISPLAY SYSTEM (KDS)
================================================================================

Architecture Overview:
- Front-End: Lightweight React / Vite SPA hosted at `khanabook.com/kds`
  (or embedded in `web-admin`).
- Backend: Spring Boot SSE Endpoint (`/api/v1/kds/stream`) + Local LAN fallback.

Zero-Auth Pairing Flow:
1. Kitchen TV opens `khanabook.com/kds`.
2. App checks localStorage for `kds_device_id`; if missing, generates UUID.
3. Calls `POST /api/v1/kds/device/register` with `{ deviceId }`.
4. Renders QR Code containing JSON `{ "type": "KDS_PAIR", "deviceId": "..." }`.
5. POS Terminal: Cashier navigates to Settings -> Kitchen Displays -> Scan QR.
6. POS calls `POST /api/v1/kds/device/pair` with `{ deviceId, restaurantId, stationId }`.
7. Kitchen TV receives instant confirmation via SSE and loads active ticket view.

Live Kitchen Screen UX:
- High-contrast Dark Theme (`#0F0E0D` background, `#FBBF24` gold accents).
- Ticket Cards sorted by `created_at ASC`:
  * Header: Table Number / Takeaway Token, Order Age (green <10m, amber 10-20m, red flashing >20m).
  * Body: Items with variant and modifier badges (`+ Extra Cheese`, `Less Spicy`).
  * Action:
    - Tap ticket: `PENDING` -> `COOKING`
    - Tap "Mark Ready": `COOKING` -> `READY` (dismisses ticket, sends alert to POS).
- Cook Summary Drawer (Batch Preparation View):
  * Aggregates identical pending items:
    Example:
    - Butter Naan: 14
    - Garlic Naan: 6
    - Chicken Biryani: 4
    - Paneer Butter Masala: 3
- Audio Siren Alert:
  * Triggers `/siren.mp3` or pleasant acoustic chime whenever a new KOT arrives.

5.3 MULTI-STATION KITCHEN PRINTING & TICKET ROUTING
================================================================================

Database Changes:
1. Room Database Migration:
   - Drop unique index `index_printer_profiles_restaurant_id_role` on `printer_profiles`.
   - Create non-unique index `index_printer_profiles_restaurant_id`.
2. Add `KitchenStationEntity`:
   @Entity(tableName = "kitchen_stations")
   data class KitchenStationEntity(
       @PrimaryKey(autoGenerate = true) val id: Long = 0,
       @ColumnInfo(name = "restaurant_id") val restaurantId: Long,
       val name: String,               // "Main Kitchen", "Tandoor", "Bar", "Bakery"
       @ColumnInfo(name = "printer_profile_id") val printerProfileId: Long? = null,
       @ColumnInfo(name = "is_active") val isActive: Boolean = true
   )
3. Update `MenuItemEntity` and `CategoryEntity`:
   - Add `station_id: Long? = null` column. Items inherit category station if null.

PrintRouter Dispatch Logic:
```kotlin
fun routeAndPrintKot(billWithItems: BillWithItems, kotEvent: KotEventEntity) {
    // 1. Group items by their assigned kitchen station
    val itemsByStation = billWithItems.items.groupBy { item ->
        menuItemDao.getStationId(item.menuItemId) ?: defaultStationId
    }

    // 2. For each station, generate sub-KOT and dispatch to station printer
    for ((stationId, stationItems) in itemsByStation) {
        val station = kitchenStationDao.getById(stationId)
        val printerProfile = station?.printerProfileId?.let { printerProfileDao.getById(it) }
            ?: printerProfileDao.getDefaultKitchenPrinter(restaurantId)

        if (printerProfile != null && printerProfile.enabled) {
            val subTicketBytes = kitchenTicketFormatter.formatSubKot(
                bill = billWithItems.bill,
                stationName = station?.name ?: "Kitchen",
                items = stationItems,
                kotRevision = kotEvent.kotRevision
            )
            printerTransport.print(printerProfile, subTicketBytes)
        }
    }
}
```
