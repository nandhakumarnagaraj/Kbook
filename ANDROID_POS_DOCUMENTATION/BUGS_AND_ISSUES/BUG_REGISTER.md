| **BUG-004** | Settings / Auth + Server | Email OTP request fails with "Failed to send verification email. Please try again." | High (P1) | **RESOLVED (code); deployment needs `MAIL_PASSWORD`** | Observed 2026-11-12 (Session 005) on device `ZA222J5KT7`: tapping `Get OTP` on the Restaurant Configuration Email field returned the inline error for a valid, unclaimed address. **Root cause:** `application.properties` defaults `khanabook.email.enabled=true` and `spring.mail.username` to a real mailbox, while `spring.mail.password` defaults to empty. `EmailNotificationService.sendVerificationOtp` therefore attempted a real authenticated SMTP send, threw, and — because the call runs inside the `@Transactional` `PasswordResetOtpService.issueEmailOtp` — rolled the OTP row back and surfaced a generic failure. The documented "development logging fallback when SMTP is unconfigured" existed only for `emailEnabled=false`, never for an unconfigured host. **Fix:** `sendVerificationOtp` now also treats a blank `spring.mail.password` as unconfigured, logs the generated code with a warning naming `MAIL_PASSWORD`, and returns without contacting the mail server; a send failure on a configured host still throws. Covered by `EmailNotificationServiceTest` (4/4 pass). **Remaining action:** set `MAIL_PASSWORD` on any deployment that must actually deliver OTP mail; until then the code only reaches the server log. |
